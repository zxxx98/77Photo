## 已运行

在 Linux ARM64 开发主机、临时 SQLite 和隔离照片目录上运行：

- `go test ./...`、`go vet ./...`、`bash scripts/check-media-contract.sh` 通过。
- photos、indexer、importer、users、storage 与 integration 包的 `go test -race` 通过。
- Web TypeScript 检查、30 个测试文件共 147 项测试、生产构建通过；构建结果同步到内嵌静态目录。
- `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build ./cmd/77photo` 通过。
- Chromium ARM64 实际 HTTP/Web 联调：上传 JPEG → 删除 → 普通原图 404 → 停服重启 → Web 恢复 → 原件逐字节相同 → 再删除 → Web 永久删除 → 恢复 404。1280×900 与 390×844 页面无脚本错误，手机布局无横向溢出。
- 服务测试覆盖上传与扫描配对的动态照片、恢复冲突、数据库最终提交失败后的重放、权限、过期清理并发、用户转移；索引测试验证回收站与唯一伴随原件经过重建仍可恢复。

- OpenAPI YAML 可解析，本地 `$ref` 均可解析。

## 验证边界

本次未进行生产数据备份恢复演练、真实断电/磁盘满故障、NAS 文件系统验证、大图库负载测试，也未完成 HEIC/所有动态照片格式的真机播放矩阵。进程重启与数据库提交失败测试不能代替断电验证。SQLite 改为 `synchronous=FULL`，写入同步开销需在部署存储上观察。

Android 原生页面本次未修改、未构建或运行模拟器；回收站管理使用 Web。旧客户端的删除请求保持接口兼容，但旧 APK 的确认文案可能仍沿用旧版本。

升级须备份完整数据根（含 `.trash` 和 `.77photo/live`）及一致性数据库。回退须恢复升级前快照，不能仅切回旧镜像读取新回收站状态。参见[回收站说明](../trash.md)。
