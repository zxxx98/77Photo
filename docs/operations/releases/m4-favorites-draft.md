# M4 个人收藏开发记录（草稿）

日期：2026-09-29 UTC。M4 开始时的基线提交为 `268029c`；随后独立提交 `38cf47e` 将 Android 版本更新到 `0.4.5`。M4 以 Web `0.1.28` 和 Android `0.4.6` 发布，尚未做目标环境验收。开发主机为 Linux `aarch64`。测试数据为临时 SQLite 与隔离照片目录中的合成 JPEG、用户和共享关系，不是生产数据库副本。

## 实现与契约

- 迁移 013 新增 `(user_id, photo_id)` 唯一收藏关系，两个外键在用户或照片永久删除时清理；账号删除的保留照片路径也会删除该用户的个人标记。
- `PUT` / `DELETE /api/v1/photos/{id}/favorite` 幂等设置与取消。新增要求照片当前可读、已索引、未在回收站；取消允许已撤权照片。普通列表和详情返回当前用户的 `is_favorite`，图库列表返回 `favorites_supported` 供旧服务端兼容判断。公开分享数据不包含个人收藏状态。
- `favorite=true` 可与目录、日期、文件名、媒体类型组合，绑定签名游标；收藏列表先从当前用户的关系索引取候选，再施加照片可见性与回收站条件。列表一次数据库查询返回每张照片的标记，无逐张数据库往返。Web 和 Android 均有查看器按钮与跨目录收藏入口；写入失败回滚乐观状态，旧服务端不展示收藏入口。
- 回收站和共享撤权只隐藏标记，恢复同一照片 ID 或重新授权后重新出现；永久删除与用户删除清理关系，照片转移不把原用户标记赋给接收者。

## 本地验证

- `go test ./...`、`go vet ./...`、`bash scripts/check-media-contract.sh` 通过。新增服务测试覆盖两用户独立标记、重复设置与取消、共享撤权与恢复、回收站与永久删除、重命名、移动与普通扫描、索引重建、用户转移、组合筛选与游标错配、Bearer HTTP 路由。迁移测试从 011 旧库升级到 013，核对原照片 ID、校验和、共享关系、原文件哈希；新增收藏再经 `VACUUM INTO` 备份恢复，`PRAGMA integrity_check=ok`。
- Web `npm ci`、全量 Vitest（33 个文件、173 项）、TypeScript 和生产构建通过；新增 API、筛选入口、查看器失败回滚、切换照片和关闭查看器期间的请求测试通过。构建产物已同步至 `internal/webassets/static`，16 个文件与 `web/dist` 的 SHA-256 逐一相同。Android JavaScript `npm ci`、typecheck、lint 和 Jest（6 套、41 项）通过，新增收藏 API 方法与 Bearer/筛选契约测试通过；查看器还会在详情加载期间保留本地收藏写入结果。
- 使用 `ANDROID_HOME=/home/ubuntu/Android/Sdk ./gradlew :app:assembleStaging -PreactNativeArchitectures=arm64-v8a` 尝试原生构建。Gradle 到 `configureCMakeRelWithDebInfo[arm64-v8a]` 时，本机 SDK 的 CMake 主机程序因缺少 `libdl.so.2` 无法启动。本环境原生构建验证不可用；未构建或改用 x86/x86_64 Android 目标。

## 本地查询性能复核

使用 `PHOTO_SEARCH_PERF=1 go test ./internal/photos -run '^TestSearchPerformance$' -count=1 -v` 在同一 Linux ARM64 主机生成 1 万和 10 万条确定性照片；一半属于成员可读的共享目录，每 102 条总照片选取一张共享照片，为管理员和成员分别建立个人收藏。每种查询预热一次，记录随后一次服务层 `List` 调用，页大小 50。下表单位为毫秒；这不是目标服务器或真实图库数据。

| 照片数 | 身份 | 无筛选 | 收藏优化前 | 收藏优化后 | 收藏+目录+日期+类型+文件名优化后 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 10,000 | 管理员 | 1.30 | 15.81 | 1.55 | 0.57（0 结果） |
| 10,000 | 共享成员 | 1.62 | 32.69 | 1.99 | 0.83（0 结果） |
| 100,000 | 管理员 | 1.20 | 173.23 | 8.40 | 5.59（5 结果） |
| 100,000 | 共享成员 | 1.74 | 334.06 | 10.04 | 5.92（5 结果） |

初版普通 `JOIN` 被 SQLite 选为先扫描 `photos_scan_status_idx`，然后按用户收藏查找并临时排序。改为从 `photo_favorites` 开始的 `CROSS JOIN` 后，查询计划先按主键中的 `user_id` 找收藏，再按照片 ID 查 `photos`；排序只针对该用户的候选收藏。无筛选时间线仍沿用 `photos_active_timeline_idx`，一次列表查询内用覆盖索引读取 `is_favorite`；服务端不逐张发起数据库调用。收藏页内存分配约 180–186 KiB，实际目标服务器性能仍需复核。
