# 回收站

Web 导航中的「回收站」用于恢复误删照片和视频。图库的单张删除、批量删除会移入回收站，默认保留 30 天；原文件与动态照片伴随文件一起保留，原内容不变。回收站中的媒体不出现在图库、地图、人物页或公开分享中。

## 使用

1. 打开「回收站」，选择需要处理的项目。可以选择当前已加载的全部可恢复项目，也可以继续加载后选择更多。
2. 点击「恢复」，默认回到各自原文件夹。也可以选择属于原照片所有者的其他目录；重名时默认保留双方并报告冲突，勾选「自动改名」后再次恢复。
3. 点击「永久删除」并确认，会彻底删除所选原文件与伴随文件，不能再通过 77Photo 恢复。
4. 「清空回收站」会分批处理当前范围内、确认操作开始前已在回收站的项目，包括未加载的内容；部分失败会显示原因并保留失败项目。未完成的文件操作不参与清空。

普通用户只能查看、恢复和永久删除自己的回收站。管理员默认查看自己的项目，可以切换到「所有用户的回收站」；清空对话框会明确显示当前范围。具有删除权限的共享成员可以移入回收站，但不能因此查看所有者的回收站或执行永久删除。

恢复不会重新启用该照片已撤销的独立分享链接。恢复到仍被公开分享或授权给家庭成员的文件夹后，照片重新遵循该文件夹的可见范围。已经下载到接收者设备的数据无法撤回。

第一版只回收照片和视频，不支持整棵目录回收。文件夹仍被回收站媒体引用时不能删除；先恢复到其他目录或永久删除这些项目。文件夹重命名/移动后，恢复默认使用该文件夹的当前位置。删除账号选择转移照片时，回收站记录的归属也随照片转移；其隔离文件路径可以保留删除当时的用户 ID，实际访问权限由当前所有者决定。

Android 现有浏览与上传保持兼容；本版本的回收站管理入口在 Web，可用手机浏览器访问。损坏文件清理和失败上传回滚仍是内部彻底清理，不进入回收站。

## 保留期与磁盘空间

`PHOTO_TRASH_RETENTION_DAYS` 默认 `30`，允许 `1–3650`。Compose 支持从 `.env` 读取该变量。每个项目在移入时确定到期时间，修改配置只影响之后删除的项目。

后台每分钟尝试恢复未完成操作，并最多永久清理 100 个到期项目。遇到其他维护任务、存储不可用或失败操作时延后处理；到期时间不是精确到秒的删除承诺。移入回收站不会释放原文件占用的磁盘空间，只有永久清理才释放。

数据放在 `PHOTO_DATA_DIR/.trash/{删除时的所有者ID}/{照片ID}/`。跨文件系统移动使用临时文件、内容校验与不覆盖的发布步骤；这时目标文件系统需有足够空间。不要手动修改回收站文件或 SQLite 中的操作记录。

## 中断与恢复

SQLite 使用 WAL 与 `synchronous=FULL`，保证文件操作日志先落盘；这会增加写入同步开销。服务先提交文件清单和操作意图，再移动或删除文件，最后完成索引变更。进程在中途退出后，启动恢复和定时任务会继续处理。移动与恢复通过文件哈希确认已完成的步骤，不覆盖已有的不同文件。

未完成项目显示处理中或重试提示，所有者/管理员可点击「重试操作」。为避免恢复路径被其他操作改变，存在未完成操作时会阻止冲突的上传、重命名、移动与扫描写入。磁盘挂载、空间、权限等问题修复后可以重试；服务器日志保留具体原因，公开 API 不暴露内部文件路径。

遇到 `SOURCE_CHANGED`，表示磁盘原文件或扫描配对的伴随文件已变化，尚未移入回收站；先重新扫描再删除。遇到恢复重名，选择自动改名或其他目录。记录状态与实际文件不符且自动恢复失败时，先保留整套数据与数据库副本，再排查；不要直接删除操作记录。

## 升级与备份

本功能新增迁移 `010_trash.sql`。旧版本已经永久删除的文件不会被恢复或伪造为回收站项目。旧动态照片缺少来源标记时保守保留伴随文件；新上传、扫描和内嵌提取分别记录来源。

「重置并重新扫描」现在保留照片 ID、回收站、分享关系和伴随原文件，只清理可重建的缩略图并刷新元数据。照片原件发生变化时仍会按现有规则使旧人脸分析失效。

按[备份与恢复](backup-restore.md)同时备份整个照片数据根（包括 `.trash`、`.77photo/live`）与一致性 SQLite 数据库。仅备份可见相册目录会漏掉回收站和部分动态照片原文件。恢复后先让服务处理未完成操作，再执行普通扫描确认状态。

不支持只换回旧版镜像读取新回收站状态。若需回退，使用升级前经过验证的数据与数据库一致性快照；先另外保存升级后产生的数据，避免回退丢失新照片。
