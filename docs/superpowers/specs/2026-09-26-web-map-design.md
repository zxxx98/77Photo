# 网页端地图设计

## 状态

2026-09-26 在对话中确认设计，并在 `feat/web-map` 分支实现。实现中的调整已写回本文：不新增地理索引、侧栏按月份分组、切换年份时尽量保持视野、导航图标改为折叠地图。

## 已确认的决定

| 问题 | 决定 |
| --- | --- |
| 底图 | 天地图：矢量底图 + 中文注记，球面墨卡托投影 |
| 入口 | 独立的「地图」导航 |
| 范围 | 地图页 + 照片详情中的位置；不做地点相册 |
| 可见范围 | 与时间线一致：管理员看到全家的照片，成员看到自己的和共享给自己的 |
| 手动设置位置 | 不做 |

## 背景

- `photos` 表从第一版起就有 `gps_latitude`、`gps_longitude` 两列，API 的 `Photo` 也会返回它们。但 `applyEXIF`（`internal/photos/service.go`）只解析了拍摄时间、厂商、型号和方向，GPS 从未写入，现有图库的位置全部为空。
- 重新扫描会对内容未变的文件也重新提取元数据并更新这两列（`internal/photos/scan.go`），修好解析后执行一次重新扫描即可补齐已有照片。
- 时间线的可见性过滤集中在 `appendVisibilityPredicate`（`internal/photos/list.go`），地图复用同一规则。
- 公开分享使用独立的 `PublicPhoto` 结构，不含位置。
- `PRODUCT_DESIGN.md` 和 D-001 把地图列为 V1 非目标，本设计由 D-012 修订。

## 目标

1. 入库和重新扫描时提取照片与视频的拍摄位置，只写 SQLite，原图不变。
2. 新增「地图」页：照片缩略图聚合点、按年份筛选、查看当前区域的照片、打开现有查看器。
3. 照片详情显示位置：坐标、小地图、「在地图中查看」和「在高德地图中打开」。
4. 不增加常驻服务、数据库或队列；地图代码按需加载，不影响图库首屏。
5. 中英文界面完整。

## 非目标

- 地点相册、逆地理编码、地名搜索。
- 手动设置、修改、清除或推测位置。
- 公开分享页的地图或位置信息。
- 瓦片代理与缓存、离线底图、其他底图源。
- 热力图、旅行轨迹、服务端聚合。
- Android 地图。接口可以复用，客户端另行设计。

## 位置提取

### 图片

- `applyEXIF` 调用 goexif 的 `LatLong()`，它会处理南北纬和东西经。HEIC/HEIF 通过现有的 EXIF 旁路文件进入同一函数；MVIMG 就是 JPEG，同样覆盖。
- 以下情况视为没有位置，两列写 NULL：
  - 缺少经纬度或 Ref 标签；
  - 非有限数值；
  - 纬度超出 ±90 或经度超出 ±180；
  - 纬度和经度都为 0（部分设备未定位时会写 0）。
- 坐标按原精度保存，不做偏移转换，见「坐标系」。
- PNG 的 EXIF 目前不解析，本次保持不变。

### 视频

- 把 `ProbeCapturedAt`（`internal/media/runner.go`）扩展为同时返回位置。ffprobe 额外读取 `com.apple.quicktime.location.ISO6709` 和 `location` 两个标签，前者优先。
- 只解析 ISO 6709 的十进制度格式（如 `+31.2304+121.4737+012.345/`），忽略高度；其他格式视为没有位置。校验规则与图片相同。
- 动态照片使用静态图的 EXIF 位置。配对的 MOV 不单独入库，不需要处理。

### 顺带写入的 EXIF 字段

`imageMetadata` 里的焦距、光圈、ISO 同样只声明、从未赋值。本次在 `applyEXIF` 中一并写入（`FocalLength`、`FNumber`、`ISOSpeedRatings`，不满足表约束的值丢弃），这样一次重新扫描就能全部补齐，免得以后再全库扫一遍。界面暂不展示这些字段。

### 已有图库

- 升级后由管理员在设置页执行一次「重新扫描」来补齐位置。重新扫描会对全部文件重新计算校验和，HEIC 还会完整解码一次，大图库可能耗时较长。进度沿用现有的扫描进度显示。
- 发布说明和部署文档写明这一步，地图页的空状态也会提示管理员。

### 数据来源的限制

- Android 10+ 在应用读取媒体时默认会抹掉 EXIF 位置，除非应用申请 `ACCESS_MEDIA_LOCATION` 并读取原始文件。这需要在 Android 客户端实现上传时处理，不在本设计范围内。
- 手机浏览器选图上传是否保留位置，取决于系统和浏览器。实施时在 iOS Safari 和 Android Chrome 上实测，并把结论写进文档。

## 存储

不新增列，也不新增索引。实测在不执行 `ANALYZE` 的数据库上，SQLite 规划器对经纬度索引、按时间排序的覆盖式部分索引等形状都不会选用，只会增加写入成本；地图查询沿用时间线已有的索引，耗时见「性能」。

## 坐标系

- 数据库和 API 始终使用 WGS-84 坐标。
- 天地图使用 CGCS2000 坐标系，与 WGS-84 只差厘米级，展示时可以忽略，因此不做任何偏移转换。避开 GCJ-02 纠偏是选择天地图的原因之一。

## 配置

- 新增可选环境变量 `PHOTO_MAP_TIANDITU_KEY`。为空时，地图页显示引导；其他功能不受影响，包括详情页的坐标和高德外链。
- 校验规则：去掉首尾空白后不能含空白或控制字符，长度不超过 128。拼接进 URL 时做查询参数转义。
- key 不写入日志，也不进入前端构建产物。启动日志只记录 `map_enabled`。
- 部署者在天地图控制台申请「浏览器端」key。白名单可以留空；如果设置了，需要包含家人实际访问用的地址（域名或 IP:端口）。
- 仓库是公开的，Compose 部署把 key 写在 `compose.yaml` 同目录的 `.env` 中（已加入 `.gitignore`），`compose.yaml` 只引用变量。

## API

服务端实现放在 `internal/photos` 中，以复用未导出的可见性谓词，由 `httpapi` 挂载到 `/api/v1/map/`。两个 map 接口都需要登录，Cookie 会话和移动端 Bearer 都支持。

### `GET /api/v1/map/config`

已配置时的响应：

```json
{
  "enabled": true,
  "provider": "tianditu",
  "tile_layers": [
    {
      "url": "https://t{s}.tianditu.gov.cn/vec_w/wmts?SERVICE=WMTS&REQUEST=GetTile&VERSION=1.0.0&LAYER=vec&STYLE=default&TILEMATRIXSET=w&FORMAT=tiles&TILEMATRIX={z}&TILEROW={y}&TILECOL={x}&tk=<key>",
      "subdomains": "01234567"
    },
    {
      "url": "https://t{s}.tianditu.gov.cn/cva_w/wmts?SERVICE=WMTS&REQUEST=GetTile&VERSION=1.0.0&LAYER=cva&STYLE=default&TILEMATRIXSET=w&FORMAT=tiles&TILEMATRIX={z}&TILEROW={y}&TILECOL={x}&tk=<key>",
      "subdomains": "01234567"
    }
  ],
  "min_zoom": 1,
  "max_zoom": 18,
  "attribution": "天地图",
  "attribution_url": "https://www.tianditu.gov.cn/"
}
```

未配置时返回 `{ "enabled": false }`。

- 瓦片地址由服务端生成，客户端只需按顺序叠加图层。以后 Android 或其他底图可以复用这个结构。
- 天地图官网「许可申请说明」页的示例把 `TILEROW`、`TILECOL` 写反了，以「地图服务」页为准：`TILEROW={y}`、`TILECOL={x}`。
- 固定使用 https。HTTP 和 HTTPS 部署都不会出现混合内容问题。

### `GET /api/v1/map/points`

返回当前用户可见、带位置的全部照片，供前端聚合：

```json
{
  "items": [
    ["p_0123456789abcdef01234567", 31.230416, 121.473701, "2026-09-01T08:30:00Z"]
  ],
  "total_photos": 12340
}
```

- `items` 每项依次为照片 ID、纬度、经度和 `captured_at`。用数组而不是对象是为了减小体积。
- 坐标四舍五入到 6 位小数（约 0.1 米）；`Photo` 接口仍返回原精度。
- 过滤条件与时间线一致：
  - `deleted_at IS NULL`；
  - `scan_status='indexed'`，排除缺失、出错和已配对的 MOV；
  - `appendVisibilityPredicate`；
  - 经纬度两列都非空。
- 排序与时间线一致：`captured_at DESC, id DESC`。前端据此取每个聚合点里下标最小的照片，也就是最新的一张，作为封面。
- `total_photos` 是当前用户可见的全部照片数（不管有没有位置），用于显示覆盖率和区分空状态。
- 客户端支持 gzip 时压缩响应。完整响应生成后计算弱 ETag，命中 `If-None-Match` 时返回 304。缓存头为 `Cache-Control: private, no-cache`。
- 不分页，也不接受筛选参数，年份筛选在前端完成。

### `GET /api/v1/photos` 新增 `bbox` 参数

- 格式为 `bbox=west,south,east,north`，先经度后纬度，与 GeoJSON 相同。
- 必须是 4 个有限数值，纬度在 ±90 内且 `south <= north`，经度在 ±180 内。不合法时返回 `400 INVALID_REQUEST`。
- `west > east` 表示跨越 180° 经线，此时经度条件为 `lng >= west OR lng <= east`。
- 带 `bbox` 时隐含「有位置」，可以和现有的 `folder_id`、`from`、`to` 组合使用。
- 和现有筛选条件一样，`bbox` 也绑定在游标里，不一致时按现有规则报错。判断是否还有下一页的 `hasPhotoAfter` 必须带上同样的条件。

## 网页端

新增前端依赖 `leaflet` 和 `supercluster`，以及需要的类型包。后端不新增依赖，goexif 已经提供 `LatLong()`。

### 入口与路由

- `AppView` 增加 `map`，路由为 `#/map`。
- 路由支持可选参数，如 `#/map?lat=31.23042&lng=121.4737&z=16`，用于从详情页跳转后定位。`readView` 需要忽略 `?` 之后的部分；参数不合法时忽略。
- 侧边栏在「文件夹」之后加入「地图」。图标用 lucide 的折叠地图 `Map`，以 `MapIcon` 导入，避免与全局 `Map` 重名；`MapPinned` 在 18px 下像人像，只用于详情中的「在地图中查看」。
- 手机底栏变为 4 项：照片、文件夹、地图、设置。`.mobile-nav` 相应改为 4 列。
- `MapWorkspace` 通过 `React.lazy` 按需加载，Leaflet 及其 CSS 一起拆成独立 chunk，加载期间显示骨架屏。
- 地图页需要铺满内容区：给 `.content-scroll` 加修饰类 `content-scroll--map`，去掉内边距并禁止整体滚动；手机上底部留出固定导航栏的高度。

### 地图库

- 使用 Leaflet（当前稳定版）加 supercluster。直接命令式调用 Leaflet，封装在 `features/map/leafletMap.ts` 中，不引入 react-leaflet。
- 地图选项：
  - 开启 `worldCopyJump`，平移跨过 180° 经线时标记仍然可见；
  - 缩放范围取自配置。
- 按配置顺序叠加底图和注记两个图层。给瓦片图层加 CSS `filter`（稍降饱和度、略偏暖），和暖白界面协调；只作用于瓦片，不影响标记。
- 署名控件只显示「天地图」并链接到官网，去掉 Leaflet 默认前缀。如果天地图要求显示审图号，实施时按其当前要求补上。
- 天地图官方图层列表里只有中文注记，英文界面下地图上的地名仍是中文，这是已知限制。

### 布局

宽屏（> 1100px）：

```
┌────────┬──────────────────────────────┬────────────────┐
│ 照片   │ [全部] [2026] [2025] [更早]  │ 此区域 238 张  │
│ 文件夹 │                              │ 2026年9月      │
│ 地图   │     ▣23           ▣8         │ ▣ ▣ ▣ ▣        │
│ 设置   │              ▣156            │ ▣ ▣ ▣ ▣        │
│        │   ▣1                  ▣42    │ 2026年8月      │
│        │                              │ ▣ ▣ ▣          │
└────────┴──────────────────────────────┴────────────────┘
```

- 地图占主要区域，年份筛选浮在地图左上角。
- 右侧是固定宽度（约 360px）的「此区域的照片」面板，按月份分组，滚动时继续加载。按天分组时，一个跨越多年的区域会变成一长列只有一两张照片的日期，按月更紧凑。

较窄屏幕（≤ 1100px，包括平板和手机）：

- 地图铺满顶栏和底栏之间的区域，年份筛选变为地图顶部一行可横向滚动的标签。
- 照片面板改为底部抽屉。收起时显示「此区域 N 张」和一排缩略图；点标题栏展开为网格，约占 70% 高度；再点一次收起。

### 聚合与标记

- 前端用 points 建立 supercluster 索引：
  - 聚合半径约 60px；
  - 最大聚合级别等于底图最大缩放级别；
  - 用 map/reduce 记录每个簇的最小下标，即最新的照片，作为封面。
- 每个聚合点是一个缩略图标记：约 56px 的圆角方块，2px 白边，轻阴影，右上角显示张数；单张照片不显示张数。颜色、圆角、阴影使用 `global.css` 中现有的变量。
- 缩略图使用现有的 `/api/v1/photos/{id}/thumbnail?size=256`，沿用图库的重试逻辑：返回 202 时稍后重试，失败时显示占位色块。
- 同一屏最多渲染约 100 个缩略图标记，超出的降级为带数字的小圆点，以控制同时发出的图片请求数。
- 标记是可聚焦的按钮，带「N 张照片」的无障碍标签，可以用回车触发。

### 交互

- **首次进入**：URL 带坐标时按坐标定位；否则缩放到能容纳所有点的范围（带留白，最多放大到 12 级）。没有任何点时显示中国全境，并叠加空状态。
- **点击聚合点**：放大到它能展开的级别（`getClusterExpansionZoom`）。如果展开级别超过底图最大缩放，或者当前已经是最大缩放，说明这些照片在同一地点。此时面板切换为「该地点 N 张」，按簇内各点的外接框列出照片，并提供「返回此区域」。
- **点击单张照片标记**：按 ID 获取照片（`ApiClient` 增加 `getPhoto`），直接打开查看器。
- **面板跟随地图**：地图停止移动约 300ms 后，面板按当前视野的 `bbox`，加上年份对应的 `from`/`to`，重新加载。发出新请求时取消上一个未完成的请求，为此 `listPhotos` 增加 `bbox`、`from`、`to` 和 `signal` 参数。
- **面板张数**：前端遍历当前年份的点，直接数出视野内的数量，不等服务端返回。
- **面板里的照片**：点击后用面板已加载的列表打开现有的 `Viewer`，左右切换只在这个区域内。在查看器里删除照片后，同步从面板和聚合索引中移除。
- **年份筛选**：「全部」加最近 4 个有照片的年份，其余年份收进「更早」下拉；只有一个年份时不显示。切换年份后，用该年的点重建索引；当前视野里仍有该年的照片时保持视野不动，否则缩放到这些点的范围。面板也改用对应的 `from`/`to`。年份按 `captured_at` 的 UTC 年份计算，与时间线的日期分组一致。

### 复用图库组件

把 `GalleryWorkspace.tsx` 中的 `PhotoTile`、`TimelineGroup` 和 `groupByDate` 抽到共享模块 `features/gallery/PhotoGrid.tsx`，由图库和地图面板共用。`TimelineGroup` 的多选参数改为可选，并支持用 `heading` 覆盖日期标题；地图面板用 `groupByMonth` 按月分组，不需要多选。

### 照片详情中的位置

- 照片有位置时，在详情元数据列表的「文件夹」之后加一行「位置」，显示保留 5 位小数的坐标。
- 下方显示一个不可拖动的小地图，约 14 级，中心放一个标记。它和地图页共用 Leaflet chunk，只在详情面板打开且地图已配置时才加载；未配置时不显示。
- 提供两个操作：
  - 「在地图中查看」：关闭查看器，跳转到 `#/map?lat=…&lng=…&z=16`。
  - 「在高德地图中打开」：打开 `https://uri.amap.com/marker?position={lng},{lat}&coordinate=wgs84&callnative=1`，坐标转换交给高德处理。
- 没有位置的照片不显示这一行。
- 网页端的 `Photo` 类型补上 `gps_latitude` 和 `gps_longitude`。

## 隐私与安全

- 新接口都要求登录，可见范围与时间线完全一致；管理员能看到所有照片，这与 D-011 一致。
- 公开分享的接口和页面不返回、不展示位置，本次不改动 `PublicPhoto`。
- 天地图 key 只通过需要登录的 `/map/config` 下发，不进入前端构建产物，也不会给公开分享页的访客。它本身就是浏览器端 key，家人的浏览器能看到它，因此部署者应在天地图控制台设置白名单。
- 瓦片由浏览器直接向天地图请求，天地图能看到访问者的 IP 和浏览的区域。部署文档要写明这一点。
- 不要对瓦片请求设置 `no-referrer`，否则依赖白名单的 key 会失效。
- 以后如果启用 CSP（内容安全策略），需要把 `https://*.tianditu.gov.cn` 加进 `img-src`。

## 性能

`tests/performance` 已加入地图测量，结果记录在 `docs/operations/performance.md`。ARM64 Neoverse-N1、10 万张照片（8 万张带位置）时：

- points：所有者 387 ms，通过共享文件夹可见的成员 713 ms，未压缩响应 4.6 MB（真实随机 ID 约 6 MB，gzip 后约 2.6 MB）。耗时主要花在纯 Go SQLite 驱动逐行读取上。成员的可见性谓词对每一行执行一次递归查询，比所有者慢约一倍；改用「先算可读文件夹集合」只能快约 25%，却会让权限规则出现第二份实现，因此保持与时间线同一谓词。
- 管理员区域查询（1°×1°）87 ms，与管理员时间线同一计划；成员和所有者多在 1–30 ms。
- 前端用 supercluster 在浏览器里聚合，切换年份时重建。
- 地图代码在独立 chunk 中：Leaflet 与封装约 45 KB（gzip），地图页约 9 KB（含 supercluster）。主 chunk 从 79.7 KB 增加到 83.1 KB（gzip），增量是文案、详情中的位置区块和两个图标。

## 验收标准

1. 配置 key 后，侧边栏和手机底栏出现「地图」，地图页显示天地图底图和中文注记。
2. 升级并执行一次重新扫描后，带 GPS 的 JPEG、HEIC/HEIF 和视频出现在地图上；没有位置或坐标为 (0,0) 的不出现。
3. 聚合点显示最新照片的缩略图和张数；点击后放大；同一地点的多张照片在面板中列出。
4. 拖动或缩放后，面板显示当前区域的照片并按月份分组；点击照片打开查看器，可以左右切换。
5. 年份筛选即时生效，面板与地图保持一致。
6. 成员只看到自己的和共享给自己的照片，管理员看到全家的照片。
7. 有位置的照片在详情中显示位置和小地图，「在地图中查看」能跳转并定位；没有位置的照片不显示位置行。
8. 未配置 key 时显示引导而不是报错；公开分享的页面和接口都不出现位置。
9. 图库首屏的主 chunk 不包含地图代码。
10. `go test ./...`、`go vet ./...`、`npm test -- --run`、`npm run typecheck`、`npm run build` 全部通过。
