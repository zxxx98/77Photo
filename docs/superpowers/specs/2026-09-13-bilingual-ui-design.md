# 77Photo 中英文双语界面设计

## 目标

为 77Photo React/PWA 前端提供中文和英文两套界面文案，首次访问默认中文，并允许用户在任意页面切换语言。登录、认证后的工作区、分享弹窗、公开分享页、错误状态和无障碍标签都属于本次范围；Go API、数据库字段、用户上传的文件名和文件夹名保持原样。

## 方案

采用不增加运行时依赖的轻量 i18n 层：

- `web/src/app/i18n.ts` 定义 `Locale`、所有文案 key、中文/英文字典、参数插值和数量/日期格式化辅助函数。
- `web/src/app/I18nProvider.tsx` 通过 React Context 暴露当前语言、切换函数和翻译函数。Provider 放在应用根部，因此登录页、认证后页面和 `#/share/:token` 公开页面共享同一套语言状态。
- `web/src/features/i18n/LanguageToggle.tsx` 提供可访问的中英文切换控件。切换后立即重渲染并写入 `localStorage`；只接受 `zh` / `en`，缺失或非法值回退为 `zh`。
- 页面组件将硬编码的 UI 文案替换成 key 调用。服务端返回的资源名称、文件名、用户名和原始 API 错误不翻译；前端已知的操作错误和状态文案使用本地 key。照片日期使用当前语言的 `Intl.DateTimeFormat`，数量使用当前语言的 `Intl.NumberFormat`。

不引入 i18next 等完整框架，因为当前界面规模适合集中式字典，且无异步翻译资源、复数规则或服务端渲染需求。组件内直接写条件分支也不采用，以避免遗漏无障碍文案和后续维护时出现中英文不一致。

## 交互与布局

- 默认语言为简体中文，而不是跟随浏览器语言；用户主动选择英文后在同一浏览器中持久化。
- 桌面端语言切换放在侧边栏账户区域附近；移动端和公开分享页提供同样可见、可键盘操作的切换按钮。
- 切换控件使用 `button`，具有动态 `aria-label` 和 `aria-pressed`，不依赖颜色区分当前语言。
- 不改变现有导航、路由、上传、分享和权限行为。语言切换不刷新页面、不重置表单或网络请求状态。
- 品牌名 `77Photo`、用户提供的文件名/文件夹名以及 API URL 不翻译。

## 文案覆盖

字典覆盖以下类别：登录标题、字段、提交和登录失败提示；主导航、搜索、上传入口、账户角色、退出登录和加载状态；时间线、筛选器、照片计数、空状态、重试和缩略图失败状态；文件夹面包屑、创建表单、空状态、加载和错误状态；上传目标、文件选择、队列状态、取消和重试；查看器导航、照片详情、重命名、移动、下载、删除、分享和操作反馈；分享弹窗的期限、密码、创建、复制和错误提示；管理员设置、账户管理、重新扫描及确认提示；公开分享页的密码门、加载、过期/不可用和只读状态。

动态文案通过插值参数生成，例如 `{count}`、`{name}` 和 `{resource}`，避免在组件中拼接语言相关的句法。对照片/文件夹和单复数分别定义 key，避免中文与英文共享不自然的句式。

## 数据流与错误处理

应用启动时 Provider 从 `localStorage` 读取语言。读取失败（例如隐私模式限制）时使用内存中的中文状态继续运行；写入失败不影响页面操作。翻译 key 缺失时开发期返回 key，生产期也不抛出异常，以免单个文案阻断整个页面。

翻译函数只处理前端拥有的稳定文案 key。API 返回的资源/权限错误在已有 catch 边界转换为本地化提示；未知错误使用通用本地化提示，不向用户直接展示数据库或服务器内部消息。切换语言不会改变 API 请求的参数和响应。

## 测试与验收

- `i18n` 单元测试验证缺省为中文、合法语言切换、非法/缺失持久化值回退、切换后的持久化，以及插值/数量/日期格式化。
- `LanguageToggle` 的测试验证切换按钮更新语言并写入存储；根级或组件级测试验证关键页面不再渲染英文硬编码路径（动态资源名称除外）。
- 保留并运行现有 Vitest、Go 测试和 Go vet。
- 运行 `npm run typecheck` 与 `npm run build`，确认嵌入式前端构建流程仍可生成产物。
- 手工验收登录页、认证后四个工作区、查看器、分享弹窗、公开分享页在中文默认状态及英文切换状态下均可操作，且窄屏下切换控件可触达。

## 非目标

- 不翻译后端 API 响应、数据库内容、用户上传文件的元数据或日志。
- 不新增语言管理后台、翻译文件热加载、自动浏览器语言探测或第三种语言。
- 不借双语改动重构现有业务流程、视觉风格或权限模型。
