# 语言切换位置与样式设计

## 目标

将 77Photo 的语言切换从认证后工作区左下角账户区移到右上角，并改为不带按钮外框的纯文字切换。登录页、认证后工作区和公开分享页统一使用右上角位置与同一视觉语言，同时保留现有中英文切换逻辑和持久化行为。

截图中的左下角账户布局仅作为当前问题的视觉参考；本次实际需求是位置、样式和跨页面一致性调整，不改变账户信息、退出登录、导航或业务流程。

## 视觉方向

- 视觉主题：安静、轻量的工具界面，让语言切换像顶栏中的辅助导航，而不是一个独立操作按钮。
- 内容层级：右上角按“语言切换 → 上传/主要动作”的顺序排列；语言切换低于主要动作，但保持足够的可发现性。
- 交互重点：当前语言通过字重表达，另一语言通过较柔和的文字颜色表达，斜杠只作为轻分隔。

## 方案

采用右上角纯文字并列方案：

```text
中文 / English       上传
```

当前语言使用较深颜色和 `font-weight: 700`，未选语言使用柔和的辅助文字色；不使用边框、圆角容器、背景填充或胶囊样式。整个控件继续使用原生 `button`，因此保留键盘操作、动态 `aria-label` 和 `aria-pressed`，视觉上通过 CSS 重置为文字链接形态。

## 组件与布局边界

### `LanguageToggle`

- 保留 `web/src/features/i18n/LanguageToggle.tsx` 的 `useI18n`、`nextLocale`、`languageToggleLabel` 和切换回调。
- 保留中文/英文标签和当前语言状态类名；只调整必要的 DOM 语义或 class 结构以支持纯文字样式。
- 不新增语言、不修改翻译字典、不改变本地存储 key。

### 认证后工作区

- 从 `AppShell` 的 `.account-area` 移除 `LanguageToggle`。
- 将 `LanguageToggle` 放入 `.topbar` 右侧，位于上传入口之前。
- 顶栏的搜索、语言切换和上传动作保持明确的间距；语言切换不与移动端菜单按钮争夺位置。

### 登录页与公开分享页

- 继续复用同一个 `LanguageToggle`，并保持右上角对齐。
- 如现有页面已有顶部品牌行，只调整布局容器，不重做品牌、表单或分享内容。

## 响应式行为

- 桌面端：语言切换位于顶栏右侧，上传入口仍是最明显的主要动作。
- 窄屏端：保留“中文 / English”完整文字，缩小相邻间距并允许顶栏内容自然收缩；不使用横向溢出。
- 控件保留清晰的 `:focus-visible` 状态，不能只依赖颜色或字重传达可操作性。
- 在公开分享页和登录页，右上角位置也必须在窄屏下保持可触达，不被品牌区域或内容容器遮挡。

## 数据流与无障碍

- 点击语言切换后立即调用现有 `setLocale`，不刷新页面，不重置表单、路由、上传选择或网络请求状态。
- `aria-label` 继续描述“切换到另一种语言”；`aria-pressed` 继续表达当前英文状态，避免仅依赖视觉样式。
- 未选语言仍可读、可点击；hover 和 focus-visible 仅增强反馈，不引入按钮外框。

## 验证与验收

- 运行现有语言切换单测，确认下一语言和无障碍标签不变。
- 增加或更新组件级检查，确认认证后工作区不再把语言切换渲染在 `.account-area`，而是在 `.topbar` 中渲染。
- 运行 `npm run typecheck` 和 `npm run build`。
- 手工检查登录页、认证后图库/文件夹/设置页面、公开分享页：中文默认、切换英文、再次切换中文、键盘聚焦和窄屏布局。
- 验收标准：所有相关页面语言切换均在右上角；没有边框按钮包裹；当前语言清晰可辨；主要动作层级不被削弱；现有语言持久化与业务行为不回归。

## 非目标

- 不改变语言默认值、语言字典、翻译覆盖范围或本地存储机制。
- 不重构顶栏、账户区、登录页或公开分享页的其他视觉样式。
- 不增加语言下拉菜单、第三种语言、图标或额外设置页。
