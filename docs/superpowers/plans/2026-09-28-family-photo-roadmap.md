# 77Photo 家庭照片管理补齐计划

日期：2026-09-28  
代码基线：`8071980`  
状态：待实施；本文记录开发路线，不代表功能已经交付或通过验收。

## 1. 目标与顺序

围绕家庭照片的日常使用，依次补齐：

**回收站 → 分享链接管理与撤销 → 基础搜索 → 收藏 → Android 视频自动备份。**

继续使用 Go、SQLite、普通文件系统和有限并发任务，不新增必需的数据库、消息队列或 AI 服务。原图内容保持不变，新功能优先复用现有权限、存储、上传和分页能力。

| 阶段 | 用户得到的能力 | 交付端 | 依赖 |
| --- | --- | --- | --- |
| M1 回收站 | 误删可恢复，明确区分移入回收站与永久删除 | 服务端、Web | 先解决扫描重建与用户数据保留 |
| M2 分享管理 | 找到已创建的分享，随时撤销 | 服务端、Web | 接入 M1 的删除、恢复规则 |
| M3 基础搜索 | 按文件名、日期、文件夹和媒体类型找照片 | 服务端、Web | 复用 M1 的可见性规则 |
| M4 收藏 | 跨文件夹保存个人精选，快速再次查看 | 服务端、Web、Android | 复用 M3 查询；依赖稳定照片 ID |
| M5 视频自动备份 | 自动上传手机中受支持的视频，明确展示失败和等待状态 | Android、服务端兼容验证 | 复用现有照片备份与上传链路 |

按上述顺序交付，每个阶段可单独发布，不必等五项全部完成。M1 和 M5 的主要工作分别是文件与数据库一致性、Android 后台运行可靠性；完成各阶段的技术验证后再估算日历工期。

本轮不包含虚拟相册、标签、AI 搜索、OCR、RAW 处理、视频转码、iOS 自动备份、访客上传和服务器整库备份系统。Android 的回收站、分享管理、完整搜索入口安排在后续端侧补齐；现有客户端仍需通过服务端兼容验证。

## 3. M1：回收站

### 用户行为与范围

- 普通删除和批量删除改为移入回收站，默认保留 30 天；页面显示剩余保留时间。
- 提供回收站列表、单张/批量恢复、单张/批量永久删除、清空自己的回收站。
- 照片所有者和管理员可以恢复或永久删除；拥有现有删除权限的共享成员仍可移入回收站，但不因此获得浏览整个回收站或永久删除的权限。
- 已删除照片从图库、地图、人物封面与计数、公开分享以及普通媒体接口隐藏。回收站预览使用独立鉴权入口。
- 恢复优先回到原文件夹；目标失效时要求选择有写权限的有效目录。重名默认报冲突，可选择自动改名，始终不覆盖现有文件。
- 第一版不支持整棵目录移入回收站。文件夹仍遵循空目录删除规则，存在回收站照片外键引用时说明原因并拒绝删除，避免产生不可恢复的目录引用。

### 实现任务

- [x] **M1.1 持久数据保护。** 调整“重置索引”流程，保留稳定照片 ID、用户关系和回收站记录；按已有路径及记录协调重新扫描，禁止简单执行 `DELETE FROM photos`。源文件变化与无法匹配的记录单独处理，不能静默丢弃用户数据。
- [x] **M1.2 数据与文件模型。** 新增回收站记录，保存照片 ID、原目录/相对路径、操作者、删除与到期时间、操作状态和需要保留的文件清单；使用 `deleted_at` 屏蔽正常查询。现有删除中间态不能自动认作可恢复照片。
- [x] **M1.3 文件事务。** 原图移入数据根内由服务端生成的 `.trash/{owner-id}/{photo-id}/` 路径；保留动态照片上传的伴随原文件及其关系，可重建的派生视频与缩略图允许重建。文件移动与数据库提交通过持久操作状态、补偿和启动恢复保证一致性。
- [x] **M1.4 接口与权限。** 普通删除改为调用移入回收站服务；恢复、永久删除、清空使用独立入口。保留现有删除请求与批量结果结构，更新响应说明及前端“永久删除”文案。内部上传失败回滚继续执行受限的彻底清理，不制造回收站垃圾。
- [x] **M1.5 维护联动。** 扫描排除回收站且不清除其索引；清理损坏文件、用户删除/转移、文件夹移动、人脸扫描和缩略图重建均按新模型处理。用户转移须同步回收站所有权及恢复目标，不能留下归属失效的文件。
- [x] **M1.6 Web 与到期清理。** 增加回收站页面、批量选择、恢复冲突处理和永久删除确认；服务端以有限批次清理到期项，持久记录失败并可重试。清空只作用于调用者有权管理的明确范围，管理员清空全站需单独明确范围。

### 关键规则

- 默认保留期建议通过 `PHOTO_TRASH_RETENTION_DAYS` 配置；配置变化只作用于后续移入的项目，已有项目使用入站时确定的到期时间。
- `.trash` 必须纳入照片数据备份。若目标存储无法安全完成移动，保持原文件并返回失败，不把文件丢失视为删除成功。
- 移入回收站时撤销该照片的单照片外链；恢复不重新启用这些链接。文件夹分享保持有效，但不显示回收站照片；恢复到仍被分享的目录后，照片重新遵循该目录分享范围，恢复界面说明此行为。
- 原件、伴随原文件和用户关系只有永久删除完成后才能彻底清理；普通缓存可随时重建。
- 用户手动永久删除可以立即执行；定时清理遇到存储根不可访问时暂停，不凭“未找到文件”批量丢弃记录。

### 验收

- [ ] JPEG、HEIC、独立视频和分离式动态照片经历“删除 → 重启 → 恢复”后，原文件哈希相同，动态照片仍可播放。
- [ ] 在文件移动前后、数据库提交前后注入失败，恢复后既不丢文件，也不把半完成项目作为正常照片暴露。
- [ ] 原目录重命名/移动、恢复重名、用户转移、批量部分失败和重复请求均有确定结果。
- [ ] 重新扫描、索引重建、缩略图重建和到期清理不会误恢复或误清除回收站内容；重建不删除唯一的动态照片伴随原文件。
- [ ] 他人及已撤权共享成员不能查看回收站；普通媒体 URL、人物缩略图和外链无法继续读取被删除照片。
- [ ] 批量永久删除与恢复并发时不发生“界面已恢复、后台又删掉”的结果。

## 4. M2：分享链接管理与撤销

### 用户行为与范围

在设置中增加“我的分享”，显示资源名称、类型、创建时间、有效期、是否设置密码及有效/过期/已撤销/资源不可用状态。支持按资源定位分享和主动撤销，撤销后不能恢复原链接，需要重新创建。

本阶段先完成列表与撤销；编辑密码、修改有效期、访问统计和允许访客下载不进入本次交付。

### 实现任务

- [x] **M2.1 管理权限与迁移。** 为分享补充管理所需的资源所有者快照与展示信息；存量记录根据现存资源回填，不虚构历史创建人。资源存在时按当前所有者/管理员权限管理；转移后同步归属，失去管理权的旧所有者不能继续管理。无有效归属的遗留记录仅管理员可管理。
- [x] **M2.2 管理 API。** 提供分页列表和幂等撤销接口，以分享 ID 操作，管理路由与已有公开 token 路由分离。Cookie 写请求继续校验 CSRF，移动 Bearer 认证沿用现有规则。
- [x] **M2.3 即时生效。** 撤销写入 `revoked_at` 并清理对应解锁会话；公开元数据、列表、图片、视频及后续 Range 请求都重新确认链接有效性。
- [x] **M2.4 管理页面。** 支持状态筛选、打开原资源、撤销确认、成功反馈和部分失败重试；资源已经删除时仍可识别并撤销其遗留分享。
- [x] **M2.5 生命周期联调。** 接入 M1 的删除/恢复规则，并验证账号禁用、用户删除/转移、目录移动以及索引维护后的管理与公开访问行为。

### 令牌与兼容规则

数据库仅保存原 token 的哈希，管理列表不能提供“重新复制旧链接”。保留首次创建成功时复制链接的流程；后续页面提供“新建分享”，不通过保存明文 token 来绕开限制。

撤销完成后新发起的访问必须失效，包括持有旧解锁 Cookie 的访问。已经下载的文件或已经完成授权并发送的数据不能远程收回，页面文案不作此承诺。

### 验收

- [ ] 用户只能管理自己有权管理的资源分享；管理员权限与现有规则一致。
- [ ] 永久链接、限时链接和密码链接均能撤销；持旧 token、旧 Cookie 或直接媒体 URL 发起的新请求均被拒绝。
- [ ] 重复撤销返回稳定成功结果，刷新与重启不改变撤销状态。
- [ ] 管理列表不返回 token、密码哈希、他人资源详情或服务器文件路径。
- [ ] 存量链接迁移后可按权限管理；未撤销的有效链接保持兼容。

## 5. M3：基础搜索

### 用户行为与范围

Web 图库增加文件名搜索、日期范围、文件夹和“全部/照片/视频”筛选，支持组合、清除条件和保留当前查询状态。动态照片按照片分类，视频筛选包含独立视频。

本阶段不搜索照片内容，不包含人物组合检索、地点名称、相机参数和全文搜索引擎。

### 实现任务

- [x] **M3.1 查询契约。** 扩展现有 `ListFilter`，增加 `q` 和 `media_type`，复用 `folder_id`、`from`、`to`。文件名采用包含匹配，明确长度限制、大小写规则及 `%`、`_` 等字符的字面量处理；所有 SQL 参数化。
- [x] **M3.2 分页与权限。** 继续按 `captured_at DESC, id DESC` 排序，将新增条件纳入签名游标及后续存在性查询。SQL 先限制可见范围和非回收站状态，再筛选和分页，不能前端拉全库过滤。
- [x] **M3.3 Web 交互。** 输入防抖、取消过时请求，筛选变化重置游标；区分空图库、无结果、加载失败。按用户本地日期生成带时区的查询边界，继续使用开始含、结束不含的服务端规则。
- [x] **M3.4 性能验证。** 用 1 万/10 万条数据验证无条件、日期、文件夹、类型和文件名组合查询，包含共享成员与管理员。记录查询计划、响应耗时及内存，再决定必要索引；不默认认为前导通配符可利用普通索引。

### 验收

- [x] 中文、英文、空格和特殊字符文件名可按约定检索，纯空白输入恢复普通列表。
- [x] 日期边界、跨时区、同时间照片、无结果和跨页组合筛选正确。
- [x] 快速修改条件不会显示旧请求结果；修改条件后使用旧游标被明确拒绝。
- [x] 私有照片、已撤销共享和回收站照片不会出现在结果、计数或预览中。
- [x] 大图库仍按页返回；在同一设备和数据集记录改动前后性能，无筛选浏览的明显回退须解决或给出可复核的原因后调整方案。

M3 的本地实现与验收证据见 [开发记录](../../operations/releases/m3-search-draft.md)。目标服务器和实体设备的发布验证由维护者后续执行。

## 6. M4：收藏

### 用户行为与范围

Web 和 Android 的照片查看器支持收藏/取消收藏，图库提供“收藏”入口。收藏是个人标记：同一张共享照片可以被多个用户分别收藏，不移动、不复制原文件，也不增加访问权限。

本阶段不引入虚拟相册、多级标签、评分或收藏公开分享。

### 实现任务

- [x] **M4.1 数据模型。** 增加以 `(user_id, photo_id)` 唯一的收藏关系和创建时间；列表、详情响应提供当前用户的 `is_favorite`，避免逐张发起额外查询。
- [x] **M4.2 API。** 使用幂等设置/取消接口，不使用无法安全重试的“翻转状态”；列表支持 `favorite=true` 并纳入游标条件。只有当前可读且未入回收站的照片能新增收藏。
- [x] **M4.3 Web 与 Android。** 增加查看器按钮、收藏列表、加载/失败反馈；请求失败回滚乐观状态，账号切换清理本地展示状态。旧服务器不支持收藏时隐藏入口或说明需升级，不影响原有浏览。
- [x] **M4.4 生命周期。** 回收站期间隐藏收藏，恢复原 ID 后重新可见；永久删除清理关系。共享撤权后立即隐藏，不泄露标题和缩略图；重新获权可恢复显示。管理员也只操作自己的收藏。
- [x] **M4.5 维护兼容。** 验证重命名、移动、普通扫描和重建不丢收藏；用户删除清理其个人标记，照片转移不把原所有者的个人收藏赠送给新用户。

2026-09-29：M4 的本地实现和自动化检查见 [开发记录](../../operations/releases/m4-favorites-draft.md)。目标服务器、旧客户端和 ARM64 实机验收仍待执行，以下验收项保留未勾选。

### 验收

- [ ] 同一照片在 Web 和 Android 上的收藏状态一致，重启和重新登录后仍存在。
- [ ] 两个用户的收藏互不影响，重复设置/取消不会产生重复记录或反向状态。
- [ ] 失去照片访问权后，收藏列表与详情均不能继续提供访问；恢复权限按约定重新显示。
- [ ] 收藏与日期、文件夹等已有条件组合时分页正确，数据库查询没有逐张收藏检查造成的额外往返。
- [ ] 删除、恢复、永久删除与索引维护后，收藏按上述规则保留或清理。

## 7. M5：Android 视频自动备份

### 用户行为与范围

在现有自动照片备份设置中增加独立的“备份视频”开关，默认关闭；用户主动开启并授权后，扫描现有和新增视频。继续使用用户选择的服务器目录、Wi-Fi 设置、服务器身份校验和上传去重。

第一版自动备份视频只覆盖服务器已接受的 MP4、WebM。独立 MOV、分离式动态照片自动配对、选择备份相册/排除截图、仅充电时上传和分片断点续传列为后续扩展。格式不受支持时明确显示原因，不能计为备份成功。

### 实现任务

- [ ] **M5.1 权限与扫描。** Android 13+ 按需申请 `READ_MEDIA_VIDEO`，Android 12 沿用适用的媒体读取权限；Android 14+ 区分完整与选择性访问。视频权限拒绝/撤销只暂停视频，已授权照片仍可备份。
- [ ] **M5.2 游标与历史迁移。** 扫描 `MediaStore.Video`，照片和视频使用独立游标，指纹包含媒体集合/卷、MediaStore 版本、ID、大小和修改时间。迁移现有照片历史时避免全量重复上传，新增设置默认不扩大上传范围。
- [ ] **M5.3 上传与状态。** 复用上传链路和服务器去重，保留按服务器身份、账号、目标目录隔离的完成历史；显示照片/视频确认数量、当前文件进度、失败原因和最近完整扫描时间。中途暂停、跳过不支持格式不能显示为全库备份完成。
- [ ] **M5.4 大文件与调度。** 先用限速网络验证超过当前 120 秒上传时限的视频，统一网络、JS 与原生任务的超时/取消规则。扫描预算控制是否开始下一文件，不能无条件截断正在正常传输的文件。
- [ ] **M5.5 可见长任务。** 对无法在系统后台窗口内完成的视频，提供用户在应用内发起的可见长传输任务，具备通知、暂停和取消；按目标 Android 版本落实合法的前台服务类型、权限与时间限制。后台不能合法继续时保存待处理状态，不循环盲重试。具体原生承载方式以 ARM64 原型验证结果写入决策记录。
- [ ] **M5.6 临时存储与重试。** 继续限制同时暂存文件数量，开始暂存前检查可用空间；不把视频整体载入 JS 内存。响应丢失后按同目录内容去重确认，网络错误和可恢复服务端错误使用退避，格式/大小限制错误等待条件变化或用户重试。
- [ ] **M5.7 真机联调。** 验证照片与视频任务公平推进，防止一条大视频反复占用每轮预算；测试多地址切换、令牌刷新、禁用备份、退出登录、目标目录删除/撤权以及重启恢复。

### 第一版的传输边界

中断文件仍从头重传，只有服务端成功响应或确认内容重复才计为完成。后台执行时间由 Android 决定，不承诺每 15 分钟一定运行，也不承诺强行停止后仍能上传。

有限后台窗口内未完成的长视频必须明确进入“待前台继续”等可操作状态，用户可完成该文件；不能仅修改超时数字便宣称支持可靠的大视频后台备份。若目标设备无法在合法长任务中完成预期大小的视频，应缩小并明示支持边界，或将断点续传提升为交付前置任务，不把无限重试作为验收通过。

### 验收

- [ ] 在 ARM64 Android 12、13、14+ 适用设备上覆盖完整授权、拒绝、部分授权和撤销；记录实际测试版本，未覆盖版本标记待验证。
- [ ] 开启后，既有和新增的受支持视频进入目标目录；照片备份、手动上传和动态照片播放不回退。
- [ ] 短视频可由后台任务完成；限速后传输超过旧 120 秒限制的文件能通过合法长任务完成，不发生固定超时循环。
- [ ] 飞行模式、Wi-Fi/蜂窝切换、进程被回收、重启、登录失效和响应丢失后，队列状态可恢复且服务端不产生重复文件。
- [ ] 不支持格式、超出服务器限制、手机暂存空间不足、服务器磁盘满都有可理解且不误报成功的状态。
- [ ] 用户关闭视频备份或退出登录后，相应传输停止；图片仍按有效设置工作，历史不会串到另一账号或服务器。
- [ ] 原视频哈希一致；记录实机峰值内存、暂存空间、耗时与后台延迟，区分“已存储成功”和“当前客户端可解码播放”。

## 9. 验证与发布

### 开发检查

按改动范围先运行相关测试，阶段交付时完成适用的完整检查。文件删除、权限、迁移、分页和后台队列需覆盖真实行为与失败路径，不以只验证界面出现按钮的测试替代。

服务端，从仓库根目录运行：

```bash
go test ./...
go vet ./...
bash scripts/check-media-contract.sh
```

Web，从 `web/` 运行：

```bash
npm ci
npm test -- --run
npm run typecheck
npm run build
```

Android JavaScript，从 `mobile/` 运行：

```bash
npm ci
npm run typecheck
npm run lint
npm test -- --runInBand
```

原生验证从 `mobile/android/` 运行；后台检查使用内嵌 JS 的 staging APK：

```bash
./gradlew :app:assembleStaging -PreactNativeArchitectures=arm64-v8a
```

Android **只构建、运行、测试和调试 `arm64-v8a` 目标**。构建主机架构与 APK ABI 是两件事；如果主机不能运行所需 SDK 工具，记录“本环境原生构建验证不可用”，继续 JavaScript、服务端和 Web 检查，转到兼容构建主机完成原生验证，绝不改用 x86/x86_64 Android 目标或模拟器。
