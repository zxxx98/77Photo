# 77Photo V1 开发任务拆分

> 执行说明：本文件是工作分解与验收清单，不是完整代码实现方案。进入具体任务时使用 superpowers:executing-plans 按任务落实；复选框用于跟踪完成状态。

**目标：** 交付适合低资源 ARM64 家庭服务器的多用户照片管理服务，完成上传、文件夹、图库、共享与部署闭环。

**架构：** 单个 Go 服务提供 REST API、托管 Web 静态资源并运行有限队列的缩略图 worker。SQLite 保存索引、权限与元数据；原图保存在普通文件系统，缓存独立且可重建。

**技术栈：** Go、SQLite、React、TypeScript、Vite、PWA；图像缩放优先评估 libvips；单容器 Docker Compose 与 linux-amd64/linux-arm64 发布。

## 2. 范围与实施前决策

| 事项 | 本拆分采用的处理方式 | 落实任务 |
| --- | --- | --- |
| V1 与 UI 示例冲突 | 以产品 V1 为准，不实现收藏、虚拟相册、地图、匿名分享和全文搜索；图库与时间线共用入口 | T01、T05、T12 |
| 回收站 | 原设计同时列为建议与 V2 候选；本拆分暂按 V1 永久删除加明确二次确认估算，实施删除前记录决定；若选择回收站，应重新估算恢复、清理、冲突处理 | T01、T09 |
| HEIC / 视频 | JPEG、PNG 为基本图像验收集；视频保存、识别与浏览器原生播放，不转码；HEIC 完整解码、视频 poster 可后续交付 | T01、T08、T13 |
| 批量操作 | V1 保留批量上传，批量移动和删除暂归 V2；不因 UI 参考图增加范围 | T09、T14 |
| 数据字段 | 统一使用 captured_at，消除设计中 taken_at 索引命名差异；补齐 EXIF 常用字段、缓存版本与扫描状态 | T01、T03 |
| 未定义接口 | 首次管理员初始化、扫描进度与删除响应在契约中明确；不开放匿名注册 | T01、T04、T16 |
| 原生依赖 | libvips/SQLite driver 的 CGO 与目标平台兼容性先验证，再确定二进制发布方式及运行依赖 | T02、T06、T10 |
