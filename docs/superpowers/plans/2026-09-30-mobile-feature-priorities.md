# 移动端功能补齐优先级

日期：2026-09-30  
状态：P0 已实现并通过自动检查；ARM64 原生构建与设备验收尚未完成。P1／P2 待实施。  
范围：Android 移动端相对当前 Web 的功能补齐，排除设置相关功能。

## 目标与当前基础

优先补齐找照片、整理照片、分享照片的日常操作，让移动端能够独立完成常用照片管理。复杂的人脸与管理员操作继续以 Web 为主，后续按实际需求补充。

当前移动端已具备时间线、收藏与收藏筛选、真实文件夹及共享文件夹浏览、视频和动态照片播放、原文件下载、系统分享、手动上传、动态照片配对上传和自动照片备份。这些能力不列为待补齐项。

系统分享是将原文件发送到其他应用；公开分享链接是让接收者通过服务器链接访问照片或文件夹，两者是不同能力。

## 优先级清单

P0 为第一批日常管理能力；P1 为第二批体验与场景扩展；P2 为低频操作和浏览优化。以下交互与验收范围是建议，实施前应结合当时的接口和权限规则细化。

| 优先级 | 待办 | 建议首版范围 | 移动端交互 | 完成标准 |
| --- | --- | --- | --- | --- |
| P0 | 搜索与筛选 | 文件名、日期范围、照片／视频、文件夹筛选；可与现有收藏筛选组合 | 搜索框与筛选面板，支持清除筛选 | 筛选与分页一致；区分图库为空和无匹配结果；日期范围错误有提示 |
| P0 | 单张与批量删除 | 单张删除、多选删除、按天选择；普通删除进入回收站 | 查看器操作菜单；长按进入多选；删除确认 | 成功项目从列表移除；部分失败保留选中并说明原因；遵守现有删除权限 |
| P0 | 回收站 | 查看自己的回收站、单张／批量恢复、永久删除、清空；恢复可选目标目录及处理重名 | 次级入口；恢复与永久删除明确区分 | 展示保留期限；恢复目标失效有处理入口；永久删除确认；失败可重试 |
| P0 | 新建文件夹 | 根目录和当前目录新建文件夹 | 文件夹页操作入口与名称输入对话框 | 新建后可立即浏览或作为上传目标；重名、无权限等错误有提示 |
| P0 | 移动照片 | 单张移动与多选移动到有权限的目录 | 查看器／多选工具栏配合分层目录选择器 | 目标目录有效且可写；部分失败可处理；移动后刷新列表与所属目录信息 |
| P1 | 公开分享链接 | 照片／文件夹生成链接、有效期、可选密码、复制与系统分享 | 资源操作菜单进入分享面板 | 链接可被 Web 访问；有效期和密码生效；创建失败明确提示 |
| P1 | 地图相册 | 地图聚合、点击地点或区域查看照片、年份筛选 | 地图浏览配合照片列表抽屉 | 只显示可访问照片；地图未启用和无位置照片时有清晰状态；可打开查看器 |
| P1 | 人物相册 | 人物列表、人物照片浏览、人物命名 | 人物卡片与照片列表；命名作为次级操作 | 人物与照片权限一致；分页正常；未启用识别或没有人物时有提示 |
| P1 | 照片详情与位置 | 尺寸、GPS 坐标、位置小地图、跳转地图及高德 | 查看器底部详情抽屉 | 缺失字段不展示虚假数据；小地图遵守服务端启用配置；位置跳转正确 |
| P1 | 取消上传 | 主动取消某个正在上传的手选文件 | 上传队列单项取消按钮 | 中止传输；明确显示取消状态并允许重试；按队列规则处理暂存文件 |
| P2 | 照片重命名 | 单张修改文件名 | 详情抽屉或操作菜单 | 名称校验、重名与权限错误明确；成功后同步列表和查看器 |
| P2 | 缩略图导航 | 查看大图时通过缩略图条快速跳转 | 查看器底部缩略图条 | 当前项高亮；跳转与前后切换一致；不挤占主要查看空间 |

多选移动是建议扩展，实施前需核对是否需要逐项调用或增加批量接口，不视为当前 Web 已具备的能力。

## 推荐实施批次与依赖

### 第一批：日常照片管理（P0）

1. 搜索与筛选，可独立开发和发布。
2. 新建文件夹与移动照片，复用分层目录选择与写权限判断。
3. 回收站与单张／批量删除作为同一交付批次，具备恢复入口后再开放移动端删除。

回收站先按普通用户的“我的回收站”设计。删除权限与恢复／永久删除权限应分别沿用服务端规则，不能因共享目录可写就允许浏览他人的回收站。恢复遇到目录失效或重名时，不覆盖已有文件。

### 第二批：分享与浏览扩展（P1）

公开分享链接、照片详情与位置、取消上传可分别发布。地图相册复用位置展示与查看器；人物相册首版聚焦浏览和命名，不要求同时交付复杂的人脸管理。

应用内查看公开分享内容也存在差距，但首版链接分享可由 Web 承接访问。是否增加原生公开分享页面与链接跳转，在链接创建能力落地后另行评估。

### 第三批：低频与体验优化（P2）

补齐照片重命名和缩略图导航，根据使用反馈决定顺序。

### 暂缓，按需求评估

- 人物合并、相似人物建议、人脸归属调整、忽略／恢复人脸。
- 管理员人脸扫描任务的启动、进度、暂停／恢复／取消及失败项处理。
- 管理员查看与操作全站回收站。

这些能力更依赖完整上下文，当前优先由 Web 承接。设置中的账号、成员、维护和分享管理不属于本文范围。

## 实施与验收约束

- 优先复用已有服务端 API、鉴权、分页和文件操作规则；缺少接口时明确记录新增范围。
- 各阶段检查无权限、离线、会话过期、空内容和部分失败；写操作失败不得显示为成功。
- 保持现有时间线、收藏、媒体播放、手动上传和自动备份正常工作。
- Android 仅支持 `arm64-v8a`，构建、设备测试和调试均使用 ARM64 目标。宿主无法运行 SDK 工具时记录原生验证不可用，继续执行不需要改变目标 ABI 的检查。
- 完成项需同时满足代码实现和适当验证，再更新下方状态；涉及原生分享、取消传输或地图跳转时补充 ARM64 设备检查。

## P0 实现与验证记录（2026-09-30）

- 复用现有服务端接口，新增移动端筛选面板、分层目录选择器、创建目录、单张／多选管理和“我的回收站”页面，无需新增服务端接口或数据库迁移。
- 文件名、日期、媒体类型、文件夹和收藏可组合筛选；日期有效性校验与分页查询保持一致。时间线支持长按多选及选择当天已加载的照片。
- 删除／恢复／永久删除按服务端 500 项上限分批；多选移动串行复用单张接口。失败项保留选择，丢失响应不自动重放，提示刷新核对。
- 移动和恢复目标限制为同一照片所有者的可写目录；只读照片管理入口禁用，混合权限批次由服务端逐项校验。删除直接调用批量移入回收站接口，动态照片伴随文件沿用服务端生命周期。
- 回收站支持到期时间、预览、指定恢复目录、重名自动改名、永久删除、清空和待处理文件操作重试；清空使用同一截止时间覆盖未加载项目。
- 自动验证：移动端 `typecheck`、`lint`、9 个 Jest 测试套件（82 个测试）通过；Android 生产 JavaScript bundle 打包通过。
- 原生验证限制：尝试 `:app:assembleStaging -PreactNativeArchitectures=arm64-v8a`，宿主 SDK CMake 启动时报缺少 `libdl.so.2`，当前环境无法完成 ARM64 APK 构建验证。未改变目标 ABI，未进行设备实测。
- 发布前仍需在可运行 SDK 工具的环境中构建 ARM64 APK，并完成 [移动端 README 的设备验收场景](../../../mobile/README.md#photo-management)。

## P1 实现与验证记录（2026-09-30）

- 按本次范围完成地图相册、人物相册与命名、照片详情与位置、取消手选上传；公开分享链接保持待实现。
- 地图复用服务端配置与位置点，使用原生图片瓦片和纯 JavaScript 聚合，支持拖动、双指缩放、地点聚合展开、重合地点列表、区域分页与年份筛选。跨日期变更线与极区范围有专门检查；底图请求不携带用户鉴权头。
- 人物相册沿用 Web 的管理员权限与识别启用配置，支持人物／照片分页、同照片多个人脸去重及人物命名；命名携带 revision，冲突保留输入并提示刷新。无需新增服务端接口或扩大权限。
- 查看器详情显示已有元数据、有效 GPS、小地图及地图相册跳转；高德链接显式使用 WGS84。无位置或缺失元数据不伪造内容，小地图遵守服务端启用配置。
- 手选队列支持取消等待／传输中的项目，AbortController 中止传输，忽略取消后的进度和成功响应。保留暂存文件供重试，传输结束后可移除并清理；离开页面或切换账号中止旧工作，避免继续启动旧队列。
- 自动验证：`typecheck`、`lint`、13 个 Jest 套件（102 个测试）全部通过；Android 生产 JavaScript bundle 打包通过；`git diff --check` 通过。
- ARM64 原生构建限制沿用 P0 记录：宿主 SDK CMake 缺少 `libdl.so.2`，尚未完成 APK 构建或设备验收。发布前执行 [P1 ARM64 设备场景](../../../mobile/README.md#map-people-details-and-manual-upload-cancellation)。
