# Android 从零设计

状态：产品与交互方向，**不是已实现的客户端**。旧 `mobile/` 工程和 Android 构建/发布流程已移除；历史计划仅供查阅，不作为新实现的规格。

页面级视觉与交互细节见 [Android UI 设计规格](android/ANDROID_UI_SPEC.md)，其中包含登录、照片时间线、文件夹、备份和图片查看器的独立预览与实现约束。

## 延续 APK 身份

新界面和业务实现从零开始，但未来 APK 的桌面显示名称仍为 **77Photo**，应用 ID 沿用 `com.photo77`，启动图标使用旧版“77”矢量设计（自适应图标原样保留，普通 PNG 已按同一设计生成）。资源及接入说明保存在 [Android 图标与名称](../../assets/android/launcher/README.md)；这些是品牌/应用身份资产，不是旧客户端代码。

![旧版 Android 启动图标](../../assets/android/launcher/res/mipmap-xxxhdpi/ic_launcher.png)

若要让新 APK 覆盖安装已有版本，还必须持有原来的生产签名密钥；仅沿用图标、名称和应用 ID 不够。

## 以现有能力为起点

77Photo 已有 Go API、React/PWA Web、用户与文件夹权限、按时间浏览照片、媒体预览与原图下载、文件夹管理、手动上传、共享，以及独立于浏览器 Cookie 的移动 Bearer 登录和设备撤销。手机端首先要把“随时看家里的照片”和“把手机照片送回家”做好，而不是把 Web 管理台的所有功能平移到小屏幕。

## 主结构

```text
首次连接（服务器地址 -> 验证连接 -> 登录）
                          |
               照片    文件夹    备份
               时间线  目录导航  上传状态
               查看器  权限操作  手选上传
                          |
                    设置（次级入口）
```

- **照片**：登录后的默认页。直接展示全部可访问媒体的时间线与密集缩略图，不提供“最近 / 全部”切换；与 Web 端一致，按 `captured_at` 的 `YYYY-MM-DD` 分组并倒序展示，每个年月日对应一个独立时间段。点按进入全屏查看，显示视频/动态照片状态，按需查看详情、下载原图。空白、加载、离线、无权限和失败状态必须可区分。
- **文件夹**：呈现服务器真实目录与共享权限；逐级进入、浏览内容，能从当前目录发起上传。只展示当前账号被允许的操作。
- **备份**：明确区分“手机待上传”和“服务器已有照片”。首版提供系统媒体选择器、目标文件夹、可恢复的上传队列，以及成功/跳过/失败与重试状态。自动备份未交付前，不展示可操作的自动备份开关或“已安全备份”的虚假状态。
- **设置**：连接与账号、设备撤销、网络及上传偏好、存储/维护动作等次级任务；管理员能力按权限出现。系统返回键、手势、状态栏和无障碍触控遵循 Android 约定。

## 交付阶段

1. **浏览闭环**：连接/登录、安全存储凭据、照片时间线、文件夹与全屏查看；复用现有 Bearer API，验证图片鉴权、权限与弱网恢复。
2. **手选上传闭环**：系统 Photo Picker 选择、目标文件夹、上传进度与可持久化队列；处理进程终止、重试、重复媒体及退出/切换服务器的隔离。明确后台执行与通知在各目标 Android 版本上的行为，再承诺“离开页面继续上传”。
3. **自动备份（单独立项）**：需要新增持续读取授权与可撤销的媒体范围配置、本机变更发现、稳定身份/去重与断点状态、队列调度及后台限制处理，并验证网络/省电策略、权限撤销和重装等边界。Photo Picker 的手选授权**不等于**可扫描整个相册；现有 Web 上传 API 也不意味着自动备份能力已具备。

每阶段通过真机与模拟器验证后才可在产品中标为可用。技术栈、最低 Android 版本和具体后台机制应在实现阶段按维护成本与目标系统限制重新评估，不继承旧工程的技术决策。

早期交互概念稿展示了未来的自动备份开关；它仅供讨论，不代表当前可交付功能。本文件的结构与阶段边界不依赖该概念稿。
