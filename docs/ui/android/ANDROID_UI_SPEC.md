# 77Photo Android UI 设计规格

状态：Android 重建的页面级视觉与交互参考，**不是已实现的客户端**。本文件补充 [Android 从零设计](../ANDROID_FROM_WEB.md)，用于约束后续 Android 客户端的页面结构、视觉语言和交互细节。

## 1. 页面范围与导航

本轮设计只定义 5 个核心界面：

1. 登录 / 服务器连接
2. 照片时间线
3. 文件夹
4. 备份 / 手选上传
5. 图片查看器

登录后的一级导航固定为：

```text
照片  |  文件夹  |  备份
```

“设置”属于次级入口，不进入底部导航；“图片查看器”由照片或文件夹中的媒体进入，也不显示底部导航。

这套页面设计不恢复旧 `mobile/` 客户端，也不预设 React Native、Compose 或其他实现技术栈。实现阶段应继续复用现有 Go API、移动 Bearer 登录和服务器权限模型。

## 2. 整体视觉方向

继续使用 77Photo Web 已确定的 **Korean Minimal / 韩式极简** 方向：温暖、克制、照片优先，不做企业后台式的重视觉框架。

### 色彩

- Warm White / 页面底色：`#FAF9F7`
- Slate Blue / 主文字与主按钮：`#3D4A5C`
- Blush Pink / 主强调：`#D4A5A5`
- Sage Green / 成功、文件夹等低饱和强调：`#A8C5B8`
- Sand / 辅助强调：`#E8D4B8`
- 错误色只用于错误语义，保持低饱和，禁止大面积高亮红色。

### 形状与层级

- 页面背景以 Warm White 为主。
- 常规控件圆角建议 16 dp。
- 卡片、底部信息面板建议 20–24 dp。
- 边框为 Slate Blue 约 8%–12% 透明度的 1 dp 细线。
- 阴影只做轻微层级提示，通常 0–2 dp elevation，不使用重阴影或玻璃拟态。
- 相册照片始终比应用 Chrome 更醒目。

### 间距与触控

建议基础间距刻度：`4 / 8 / 12 / 16 / 24 / 32 dp`。

Android 可交互控件最小触控区域按 **48 × 48 dp** 设计。图标本身可更小，但触控容器不能缩小。

### 字体建议

优先使用 Android 系统字体 / Roboto / Noto Sans CJK：

- 页面标题：24–28 sp
- 区块标题：18 sp
- 正文 / 主要控件：16 sp
- 次要文本：14 sp
- 元信息：12–13 sp

主文字使用 Slate Blue，而不是纯黑。

## 3. 登录 / 服务器连接

![登录页面](./login.jpg)

### 目标

自托管产品的“连接服务器”和“登录账号”应在同一流程内完成，减少首次使用时的页面跳转。

### 页面结构

- 顶部保留 77Photo 品牌标识与简短说明。
- 服务器地址输入位于账号密码之前。
- 服务器地址支持历史地址 / 下拉选择，但不能自动连接未经用户确认的新地址。
- 账号、密码为常规输入框，密码支持显示 / 隐藏。
- 主操作只有一个明确的“登录”按钮。
- “连接设置”作为次级入口，用于网络策略、服务器切换或高级连接配置。

### 交互要求

- 对服务器地址做格式校验，并将“无法连接服务器”“TLS / HTTP 策略错误”“账号或密码错误”区分显示。
- 登录成功后默认进入“照片”时间线。
- “保持登录状态”只在安全凭据 / Session 能可靠保存时显示，并且不能把保存失败伪装为成功。
- **当前后端没有对应密码找回能力时，应隐藏“忘记密码”入口。** 概念图中的该文字只是视觉占位，不作为功能要求。
- 登录中必须有 loading 状态，并避免重复提交。

## 4. 照片时间线

![照片时间线](./gallery.jpg)

### 核心规则

**照片页不提供“最近 / 全部”切换，也不再单独提供一个“时间线”Tab。**

登录后进入照片页时，直接展示当前账号有权限查看的**全部照片和视频时间线**，按拍摄时间倒序排列。

建议排序优先级：

```text
captured_at
→ file_created_at / 可用文件时间
→ indexed_at（最终兜底）
```

### 页面结构

- 顶部：`77Photo` 标题 + 设置入口。
- 中间：按日期分组的媒体网格。
- 底部：照片 / 文件夹 / 备份三项导航。
- 手机默认采用紧凑 3 列网格；根据实际屏幕宽度可自适应为 2–3 列。
- 缩略图间距建议 2–4 dp，让照片形成连续浏览节奏。

### 日期分组

概念图使用“今天 / 昨天 / 更早”表达时间线结构，但实际实现应优先显示更精确的日期：

```text
今天
昨天
9 月 23 日
9 月 22 日
...
```

跨较长时间后可按月份形成区块，但不要把所有旧照片永久塞进一个模糊的“更早”分组。

### 媒体标识

- 视频：右下角使用小型视频图标 + 时长。
- Live / Motion Photo：使用克制的小型状态徽标，不把它当普通视频显示。
- 普通图片不叠加无必要文字。
- 点击进入查看器。
- 长按可预留给未来多选，但在批量操作未实现前不要展示虚假入口。

### 加载与性能

- 使用 cursor pagination / lazy loading。
- 首屏优先加载缩略图；进入查看器后加载 preview。
- 缩略图未完成时保持稳定占位尺寸，避免网格跳动。
- 必须区分：加载中、空图库、离线、鉴权过期、无权限、缩略图失败。

## 5. 文件夹

![文件夹页面](./folders.jpg)

### 定位

文件夹页面展示的是服务器上的**真实目录结构**，不是虚拟 Album 系统。

### 页面结构

- 顶部标题“文件夹”。
- 如果当前用户具备创建文件夹权限，可显示右上角“+”。
- 每个文件夹项包括：
  - 封面缩略图；
  - 文件夹名称；
  - 照片 / 视频数量；
  - 必要时显示“共享”等轻量状态；
  - 进入箭头。
- 底部保留一级导航。

### 交互

- 点击文件夹逐级进入。
- Android 系统返回键 / 手势返回上一级目录。
- 在具体目录内可以查看该目录媒体，并从当前目录发起上传。
- 移动、重命名、删除、创建等操作必须依据服务器返回的权限决定是否展示。
- 不在 UI 中创造与磁盘目录脱离的“相册”概念。

## 6. 备份 / 手选上传

![备份页面](./backup.jpg)

### 定位

当前阶段的“备份”页面本质是**可靠的手选上传队列**。

在自动备份完整交付之前，界面不得暗示“手机相册已经自动、安全地全部备份”。

### 页面结构

- 顶部标题“备份” + 次级菜单。
- 状态摘要：等待、进行中、失败。
- 主 CTA：“选择照片与视频”。
- 目标文件夹选择项。
- 上传队列。
- 底部一级导航。

### 选择与上传

- 首版优先使用 Android Photo Picker。
- 选择照片 / 视频后再明确目标服务器文件夹。
- 队列项展示：
  - 缩略图；
  - 文件名；
  - 当前状态；
  - 上传进度；
  - 暂停 / 更多操作；
  - 失败后的重试按钮。
- 至少区分：等待、上传中、成功、跳过、失败。
- 队列状态应持久化，应用重启后能够恢复可恢复任务。

### 文案边界

只有在后台执行、权限、去重、断点、系统省电限制等自动备份条件全部验证后，才能新增“自动备份”开关和“已备份完成”之类的全局状态。

## 7. 图片查看器

![图片查看器](./viewer.jpg)

### 页面结构

查看器让媒体占据大部分屏幕，应用操作退居次要位置。

- 顶部悬浮：返回、分享、下载、更多。
- 主体：高质量 preview。
- 底部信息区域：
  - 文件名；
  - 拍摄时间；
  - 所在文件夹；
  - 分享；
  - 下载原图；
  - 移动；
  - 删除；
  - 详情。

概念稿中的底部区域可以实现为可折叠 Bottom Sheet：默认只露出必要信息，需要时向上展开完整 metadata。

### 交互

- 左右滑动切换前后媒体。
- 图片支持双击 / 双指缩放。
- 视频显示原生播放控制。
- Live / Motion Photo 应以“照片 + 动态片段”的体验呈现，而不是把配对视频当普通视频页。
- 默认加载 preview；只有用户明确选择“下载原图 / 查看原图”时才读取完整原文件。
- 删除操作必须二次确认。
- 用户没有写权限时隐藏移动 / 删除。
- 分享按钮对应后端已有只读分享链接能力；若某一资源不可分享，不显示虚假可用状态。
- 查看器不显示底部主导航。

## 8. 全局状态与无障碍

所有 5 个页面必须统一处理：

- Loading / skeleton
- Empty
- Offline / network unavailable
- Server unavailable
- Authentication expired
- Permission denied
- Media preview failed
- Upload failed

无障碍要求：

- TalkBack 可读名称完整。
- 所有图标按钮必须有 accessible label。
- 文字和背景达到 WCAG AA 对比度。
- 不只依赖颜色传达状态。
- 尊重系统 reduced motion 设置。
- 适配 Android edge-to-edge 与状态栏 / 导航栏 insets。
- 查看器顶部图标颜色应根据媒体背景保证可见性。

## 9. 页面关系

```text
服务器地址 + 登录
        |
        v
      照片  <------->  文件夹  <------->  备份
        |                 |
        +------> 图片查看器 <------+
        |
        +------> 设置（次级入口）
```

底部导航只存在于“照片 / 文件夹 / 备份”三个一级页面。

## 10. 实现验收重点

后续真正开始 Android UI 实现时，至少检查：

- [ ] 照片页没有“最近 / 全部”筛选，打开即为完整时间线
- [ ] 三个一级页面底部导航一致
- [ ] Viewer 和 Login 不展示底部导航
- [ ] 文件夹是真实服务器目录
- [ ] Backup 首版只承诺手选上传，不伪装自动备份
- [ ] 权限不足时不展示不可用的编辑 / 删除操作
- [ ] preview 与原图加载分离
- [ ] Live / Motion Photo 不以普通视频样式展示
- [ ] 48 dp 最小触控区域与 TalkBack 可用
- [ ] 页面颜色、圆角、间距与 Web 的 Korean Minimal 视觉语言保持一致
